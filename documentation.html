AppStudio Framework & CLI

Write one declarative UI application in spid3r (.matrix) and run or package it natively for Desktop, Web, Android, and iOS — with zero Node/npm or JS framework dependencies.

Single Codebase (`app.matrix`) Incremental DOM Morphing Web Worker WASM Runtime Unified Host Effects Protocol

1. What Is AppStudio?

AppStudio is a lightweight, batteries-included UI framework and multi-target build CLI written in Spid3r v1.1.1. Instead of maintaining separate apps in Kotlin, Swift, HTML/React, and Electron, you describe your screens, navigation tabs, state, storage, theme tokens, and handlers once in app.matrix.

Target Host Runtime Build Output Requirements to Run / Package
desktop Native OS WebView + compiled Spid3r VM Self-contained executable (embedded bytecode + host.html) spid3r CLI only
web Browser Web Worker + spid3r.wasm (with main-thread fallback) index.html, app.matrix, spid3r.js, spid3r.wasm, wasmworker.js spid3r CLI; any HTTP server to view
android Android WebView + WebViewAssetLoader + spid3r.wasm Full Gradle Kotlin project (AndroidApp/) with hardware Back support Java + Android Studio / Gradle + Android SDK for APK
ios iOS WKWebView + custom WKURLSchemeHandler (appstudio://app/) + spid3r.wasm SwiftPM + xtool.yml package (works from Windows/Linux/macOS via xtool) xtool (deploy to iPhone without a Mac) or Xcode

2. How It Works (Runtime Architecture)

AppStudio shares one declarative component model across two execution modes tailored to each platform:

Mode A — Native Desktop (`run`, `dev`, `desktop` build)

main.matrix shims → App.run() injects CSS & ClientJS → window.__studio.patch() → window.ipc → Bridge

State stays live in the native Spid3r process. After startup, App.render() patches DOM differences via window.__studio.patch and flushes queued host effects via flush_native_effects().

Mode B — Web, Android & iOS (`wasm_run` Stateless REPL)

FlatKit.matrix bundles single app.matrix → wasmworker.js loads spid3r.wasm → Envelope JSON in → @@STUDIO_FRAME@@ out

Every UI event posts a JSON envelope (event, router, state, storage, theme, theme_version, caps) into the off-thread Web Worker, which returns one atomic frame updating DOM morph, localStorage persistence, dirty CSS, and side effects.

Key Architectural Highlights

  • FlatKit Bundler (tools/FlatKit.matrix): Uses a string/comment-aware lexer to bundle studio/* (in deterministic fw_order) plus multi-file user imports into one isolated WASM-ready file without breaking comments, strings, or string interpolations.
  • DOM Morphing (studio/ClientJS.matrix): Diffs only changed elements, attributes, and text nodes, reuses elements with data-key, and preserves focus/cursor position plus active typing when debounced input events are still pending.
  • Worker + Busy Bar (targets/wasmworker.js & targets/wasmhost.template.html): Keeps the UI responsive while evaluating WASM off the main thread, displays a slim #studio-busy indicator after 120ms on slow evaluations, and falls back to main-thread execution if Workers are blocked.
  • CSS Dirty-Tracking (studio/Theme.matrix): Increments Theme.version() on theme mutations so subsequent frames emit "css": "" unless the theme actually changed.

3. All CLI Commands (`studio.matrix`)

Run all CLI operations from the AppStudio repository root using spid3r run studio.matrix <command>:

Command Purpose & Behavior
spid3r run studio.matrix doctor Audits installed tools: spid3r, xtool, swift, java, gradle, adb, and ANDROID_HOME / ANDROID_SDK_ROOT.
spid3r run studio.matrix gui [appdir] Launches the full AppStudio GUI Control Center (or double-click AppStudio.bat) for visual project switching, cross-platform builds/previews, iOS .ipa USB installs, test runs, and missing-tool downloads.
spid3r run studio.matrix new <AppName> [outdir] Creates a self-contained project from templates/starter/ and vendors studio/* into vendor/studio/ alongside targets/host.html and studio.json.
spid3r run studio.matrix run <appdir> Launches the native desktop preview window (`spid3r gui <entry> --html <host>`). Close the window to exit.
spid3r run studio.matrix dev <appdir> [--target web|ios] [--host IP] [--port N] Launches native hot-reload preview, serves build/web/ over concurrent HTTP with auto-rebuild (use --host 0.0.0.0 for LAN/phone Safari preview), or deploys to iPhone when --target ios is passed.
spid3r run studio.matrix check <appdir> Runs static analysis (`spid3r check`) on the app entry without opening a GUI window.
spid3r run studio.matrix build <appdir> [--target T] [-o <outdir>] Packages the app (including assets/ & studio.json icon/theme/SDK settings) for web (default), android, ios, or desktop.
spid3r run studio.matrix ios <install-tools|status|setup|devices|run|install|uninstall|launch> Manages AppStudio's cached xtool 1.24.0 iOS toolchain (WSL2/Linux/macOS), checks device prerequisites, and deploys/launches directly on iPhone.
spid3r run studio.matrix test [filter] Runs spid3r fmt --check, spid3r check --deny-warnings on every file, and all test suites in tests/.
spid3r run studio.matrix clean [appdir] [--cache] Deletes <appdir>/build, temporary flags, and leftover test directories (plus .studio-cache/ when --cache is passed).
spid3r run studio.matrix upgrade <appdir> Refreshes vendored vendor/studio/*.matrix and targets/host.html inside an app created with studio new.
spid3r run studio.matrix help Displays CLI command summary and flags.

Target Build Examples

# Launch Complete GUI Mode (Control Center)
spid3r run studio.matrix gui

# Check environment

# Create a new project
spid3r run studio.matrix new MyApp

# Run & hot-reload during development (native, desktop browser, or phone on LAN)
spid3r run studio.matrix run examples/demo
spid3r run studio.matrix dev examples/demo
spid3r run studio.matrix dev examples/demo --target web --host 0.0.0.0 --port 8080

# Managed iOS toolchain & USB deployment (WSL2 / Linux / macOS)
spid3r run studio.matrix ios install-tools
spid3r run studio.matrix ios status
spid3r run studio.matrix ios run examples/demo

# Package for each platform (optional -o sets custom output directory)
spid3r run studio.matrix build examples/demo --target web
spid3r run studio.matrix build examples/demo --target desktop
spid3r run studio.matrix build examples/demo --target android
spid3r run studio.matrix build examples/demo --target ios

# Verify formatting, compiler warnings, and all 4 test suites

After building: Web builds emit a PWA (manifest.json + sw.js offline cache + iOS Home Screen meta tags), so phones on the same Wi-Fi can open http://<PC-IP>:8080/index.html and tap Share → Add to Home Screen. For native targets, run spid3r run studio.matrix ios run <appdir> (managed xtool 1.24.0) for iPhone, open build/android/AndroidApp/ in Android Studio (or run gradle assembleDebug) for Android, or launch the binary in build/desktop/.

5. Quick Start & Project Layout

Every AppStudio app uses app.matrix for UI and logic, plus a minimal main.matrix that connects the entry-only native GUI functions:

app.matrix

import "studio/App" as appkit;
import "studio/Components" as ui;
import "studio/State" as state;

fn inc(_ev) {
    state.set("n", state.get_or("n", 0) + 1);
}

fn Home() -> map {
    let n = state.get_or("n", 0);
    return ui.page([
        ui.navbar("Counter"),
        ui.card([
            ui.title("Count: " + string(n)),
            ui.spacer(12),
            ui.button("Increment", "inc")
        ])
    ]);
}

public fn studio_app() {
    return appkit.App("Counter", "com.example.counter", "1.0.0")
        .page("Home", Home)
        .handler("inc", inc);
}

main.matrix & Directory Tree

import "app" as app;

fn studio_title(t: string) { gui_title(t); }
fn studio_html(h: string) { gui_set_html(h); }
fn studio_eval(js: string) { gui_eval(js); }
fn studio_on(n: string, cb) { gui_on(n, cb); }
fn studio_emit(n: string, p: string) { gui_emit(n, p); }

fn main() -> int {
    return app.studio_app()
        .bridge(studio_title, studio_html, studio_eval, studio_on, studio_emit)
        .run();
}
MyApp/
├── app.matrix          # Screens, state, handlers, studio_app()
├── main.matrix         # Entry file + 5 native GUI shims
├── studio.json         # App name, bundleID, version, entry

Run natively with spid3r run studio.matrix run examples/demo or preview on desktop and mobile Safari via spid3r run studio.matrix dev examples/demo --target web --host 0.0.0.0 --port 8080.

7. Key Technical Details & Best Practices

Named Handlers for Async & Lists

On Web/Android/iOS, WASM re-evaluates fresh on each event. Register async HTTP callbacks with app.handler("on_data", on_data) and pass "on_data" as a string to Http.get_async(url, "on_data"). Add "key": "..." props on dynamic cards or list items so DOM morphing emits data-key and reuses nodes across reorders.

Security & Fault Isolation Built In

Util validates image/avatar URLs (safe_url), sanitizes CSS variables (esc_css_val), and escapes icons, attributes, and text. Both native desktop and WebView hosts include restrictive CSP headers. Boot, handler, and render failures render structured error cards instead of white screens.

Host Capabilities (`Bridge.caps()`)

Before running boot or event handlers, the host runtime populates platform ("native", "web", "android", or "ios"), prefers_dark, and viewport_width, enabling adaptive layouts and platform-aware logic inside one codebase.

Runtime, Toolchain & PWA Caching

.studio-cache/ (gitignored) caches both the versioned WASM runtime (spid3r.js + spid3r.wasm) and the managed xtool 1.24.0 iOS toolchain (studio ios install-tools). Built Web apps also ship manifest.json and sw.js for offline PWA caching and iOS Home Screen installation.
